## Key Changes Made

### 1. ForgeExec Service Layer (`ui/services/forgeexecService.ts`)

**Purpose:** Replace Gemini AI validation with real ForgeExec backend calls

**Functions:**
- `submitEvent()` - Submits events to ForgeExec API
- `getJobDetails()` - Fetches job details
- `getActiveJobs()` - Fetches all active jobs
- `getTechnicianStatus()` - Fetches technician status
- `validateKernelEvent()` - Backwards-compatible validation wrapper

**API Endpoints Expected:**
```typescript
POST   /api/events              // Submit execution event
GET    /api/jobs/:jobId         // Get job details
GET    /api/jobs?state=ACTIVE   // Get active jobs
GET    /api/technicians/:id     // Get technician status
```

### 2. Event Type Mapping (`ui/services/eventTypes.ts`)

**Purpose:** Align UI event types with ForgeExec NLE event definitions

Maps UI actions to proper ForgeExec event types from:
- `verticals/next-level-electric/events.ts`

### 3. App.tsx Updated

**Changes:**
- Imports `forgeexecService` instead of `geminiService`
- Events now route to real ForgeExec backend
- Gemini features preserved for auxiliary functions (NEC search, supply stores)

## Setup Instructions

### Prerequisites

1. **Backend Running:** ForgeExec backend must be running on port 3000
2. **Node.js:** Version 18+
3. **API Key:** Gemini API key for auxiliary features (NEC search, supply stores)

### Step 1: Install Dependencies

```bash
cd ui/
npm install
```

### Step 2: Configure Environment

Create `.env.local`:

```bash
# ForgeExec Backend URL (default: http://localhost:3000)
VITE_FORGEEXEC_API=http://localhost:3000

# Gemini API Key (for auxiliary AI features)
VITE_GEMINI_API_KEY=your_gemini_api_key_here
```

### Step 3: Update Gemini Service

Edit `ui/services/geminiService.ts` line 5:

```typescript
// Before
const ai = new GoogleGenAI({ apiKey: process.env.API_KEY || "" });

// After
const ai = new GoogleGenAI({ apiKey: import.meta.env.VITE_GEMINI_API_KEY || "" });
```

### Step 4: Start Development Server

```bash
npm run dev
```

UI will be available at: `http://localhost:5173`

## Event Flow Example

### Technician Arrives at Job Site

1. **UI Action:** User taps "Arrived at Job" button
2. **Event Creation:**
   ```typescript
   {
     type: 'TECHNICIAN_ARRIVED',
     payload: {
       jobId: 'JOB-001',
       technicianId: 'TECH-001',
       gpsLocation: { latitude: 37.7749, longitude: -122.4194 }
     },
     timestamp: '2026-01-04T10:00:00Z',
     sourceId: 'technician-app'
   }
   ```
3. **ForgeExec Processing:**
   - Validates event against current state (DISPATCHED)
   - Checks state machine: DISPATCHED → ON_SITE (valid)
   - Updates job state to ON_SITE
   - Triggers Samsara GPS adapter (log arrival)
   - Returns success response
4. **UI Update:**
   - Receives `{ accepted: true, newState: 'ON_SITE' }`
   - Updates local job state
   - Shows success message: "STATE_TRANSITION_ACCEPTED"

## UI Constraints (Enforced)

✅ **UI DOES:**
- Display current job state
- Emit events on user actions
- Show validation errors from backend
- Capture photos/GPS/voice notes
- Render job lists and details

❌ **UI DOES NOT:**
- Decide if actions are allowed (ForgeExec decides)
- Calculate derived values (totals, durations)
- Store authoritative job state
- Retry failed events automatically
- Modify event payloads

## Dual-Mode Operation

### Development Mode (Mock Data)

When ForgeExec backend is not running:
- UI uses `MOCK_JOBS` from `constants.tsx`
- Events show connection errors but UI remains functional
- Allows design/layout development without backend

### Production Mode (Real Backend)

When ForgeExec backend is running:
- All events route to `/api/events`
- Real-time state updates from backend
- Full integration with Jobber, Samsara, QuickBooks, Twilio

## Troubleshooting

### UI Shows "Unable to connect to ForgeExec backend"

**Cause:** Backend not running or wrong URL

**Fix:**
1. Start ForgeExec backend: `npm test` (in root)
2. Check `.env.local` has correct `VITE_FORGEEXEC_API`
3. Verify CORS is enabled on backend

### Events Are Rejected

**Cause:** Invalid state transition or missing payload fields

**Fix:**
1. Check backend logs for rejection reason
2. Verify event type matches `NLEEventType` in `events.ts`
3. Ensure all required payload fields are present

### Gemini Features Not Working

**Cause:** Missing or invalid Gemini API key

**Fix:**
1. Get API key from: https://ai.google.dev/
2. Add to `.env.local` as `VITE_GEMINI_API_KEY`
3. Restart dev server: `npm run dev`

## Architecture Compliance

✅ **UI is a Dumb Terminal:** All business logic in ForgeExec/Kernel  
✅ **Event-Driven:** All actions emit events, wait for validation  
✅ **Read-Only State:** UI displays state, never modifies it  
✅ **No Derivations:** No computed values in UI  
✅ **Deterministic:** Same event + state = same result
